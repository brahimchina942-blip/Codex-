# 开发依据与需求分析

来源：[开发翻译智能体，共享聊天记录](https://chatgpt.com/share/6acf192a-496c-83e8-82cf-e0e092a12c35)，2026-10-14读取。共享记录包含一条核心用户需求和多段重复/扩展的助手方案，下表区分用户明确目标和方案建议，避免把全部建议当成必须一次完成的功能。

## 项目定位

**Morocco AI CRM — 摩洛哥智能客户翻译助手**。为中国—摩洛哥货代操作者解释混合语言聊天，把客户沟通转为中文参考、可复制回复和独立客户记忆。

核心路径：上传截图/粘贴原文 → 读取当前客户上下文 → 千问识别、翻译、提取事实及回复 → 人工确认归属与内容 → 保存消息和版本化记忆 → 下一次沟通检索引用。

| 项目 | 聊天记录中的性质 | 首版处理 |
|---|---|---|
| 网页智能体，接千问思考 | 用户明确要求 | 多模态HTTP接口，配置密钥后可调用 |
| 上传聊天截图 | 用户明确要求 | 上传、粘贴、拖入，多图支持 |
| 类微信聊天界面 | 用户明确要求 | 客户/聊天/档案三栏与手机切换 |
| 英法阿拉伯语组合句理解 | 用户明确要求 | 提示明确包含Darija、Arabizi和混合句；需真实样本验证 |
| 翻译中文并给回复参考 | 用户明确要求 | 逐条中文、三种风格与中文意思 |
| 自动建档和长久记忆 | 用户明确要求 | AI提取候选档案，人确认后创建/归档；SQLite保存 |
| 别只依赖模型本身记忆 | 方案核心原则 | 独立数据库和上下文检索 |
| 三层记忆、事实来源/失效 | 方案扩展建议，直接影响可靠性 | 聊天/事实/检索上下文，保留版本 |
| 截图重叠去重 | 方案建议，日常使用必需 | 同截图+连续重叠保守去重 |
| Next.js/React + SQLite | 技术建议 | 首版Node.js24内置HTTP/SQLite+原生JS；接口支持后续迁移 |
| 双模型（Plus + OCR） | 技术建议 | 首版一个多模态模型，OCR后续按实际识别结果增加 |
| 合并重复客户、全库智能筛选 | 后续管理建议 | 暂缓，需要更完整身份/订单模型 |
| 团队权限和跨设备部署 | 后续建议 | 本地单用户、可选密码；团队系统后续开发 |

## 三个需要纠正的预期

1. “永久记住”由应用数据库、磁盘和备份负责。模型不会自动拥有独立可靠的永久记忆，只有检索后注入的上下文。
2. “准确翻译”不能在没有真实摩洛哥混合语样本时承诺。模型输出须允许歧义、看不清和发送方未知，并可人工校对。
3. “自动建客户档”不等于凭名字合并。两个Mohammed可能是不同客户，截图身份是候选线索，不应直接决定资料归属。

## 首版范围与验收

- 不带密钥也可启动界面，固定演示必须明确标注；不能假装翻译任意截图。
- 带有效地域接口与密钥后：截图得到可校对草稿，用户确认之前不进入正式客户档。
- 选择A客户产生的分析不能归档到B；同名客户可分开存在。
- 15CBM→20CBM：当前体积为20CBM，15CBM保留为历史且可查原消息。
- 同一截图再次导入不增加相同消息；无法确定的孤立短句保留。
- 修改来源消息后关联记忆进入待复核，旧回复停止作为可复制建议展示。
- 应用重启后消息、事实、截图、草稿保留；复制回复不触发任何发送。
- 桌面三栏、手机可切换客户/聊天/档案，中文与阿拉伯语分别正确展示。

## 行业规则

使用正式品牌 **Barsan International Freight Forwarding**。操作者是中国女性，中文界面，客户语言版本自然友好。已知的信息不要重复询问；缺失时优先核对货物类型、重量、体积、摩洛哥收货城市。不能把“门到门”直接认定为DDP含税；清关、税费、派送和覆盖范围必须确认。

不虚构运价、时效、税率、HS编码、清关结果或“已经替客户办好”的动作。报价需记录币种、运输范围和时间条件；“Any update?”有多个候选事项时应澄清。

## 交付状态

交付的是本地可运行源码项目，包含已实现的首版、测试、配置示例与继续开发约定。没有接入用户真实密钥、没有真实客户导入、没有公开部署，也没有创建ChatGPT侧栏的“项目”容器；代码项目目录与ChatGPT界面项目是不同对象。

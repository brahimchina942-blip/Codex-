# 后续开发路线

## 已实现：本地核心版本 v0.1

界面、客户建档、千问多模态调用、人工审核、SQLite消息及事实、三种回复、截图来源、保守去重、检索上下文、校对失效、登录及备份脚本。

## 下一步：真实业务验收

在用户Mac本地配置百炼Key及地域接口，选10—20份经许可的真实聊天样本。覆盖纯法语、纯英语、阿拉伯字母Darija、Arabizi、混合句、重叠截图、模糊文字和消息发送方歧义。逐条核对数字、币种、货物单位、客户语气与业务意图。

验收后固定可用模型及配置；统计识别失败/人工修改比例，决定是否增加独立OCR步骤。若图文识别偏差大，先做截图裁切或OCR两阶段，不靠增加CRM功能掩盖翻译问题。

## 数据模型增强

v0.2已完成：同一客户多个运输需求、按需求隔离的消息/货物事实/去重/AI上下文、人工报价记录、报价来源变更失效，以及v1→v2兼容迁移。尚未实现报价改价流程、已失效报价人工复核、混合多票截图逐条分配及旧记录搬迁。

优先增加 `shipments`（同一客户多票货）、`quotes`（金额/币种/时效/覆盖范围）、事实冲突确认与事实人工修订。业务事实归属于具体运输需求，避免把新货物20CBM覆盖老订单15CBM。

增加完整日期与消息顺序审核、截图气泡定位、近似OCR去重预览、撤销一次导入。孤立短句、同名客户和同日不同截图不能靠文本Hash自动合并。

进一步完善原消息删除后的截图清理、客户删除/恢复、备份恢复自动检查和数据保留管理。为数据库使用显式版本迁移。

## 客户管理与检索

客户重复候选只提示，不自动合并；正式合并需展示两边记录、处理冲突并可撤销。增加筛选字段（最近询价、城市、货物、待跟进状态）；自然语言筛选转换为参数化查询，不能执行模型生成的任意SQL。

客户历史规模扩大后评估FTS5、中文分词或向量检索。仍按customer_id过滤，再做相似度排序，不跨客户泄漏上下文。加入独立跟进任务和完成状态，避免依赖一个自由文本字段。

## 前端和部署

若用户希望Next.js/React，复用 `docs/API.md` 中接口及SQLite存储层，替换前端，先保持行为与数据一致。移动端加强截图快捷录入和长聊天浏览。

正式云端/跨设备前：单用户密码升级为账号+权限、HTTPS、加密备份、访问审计和恢复演练；按需SQLite迁移PostgreSQL。模型接口费用与日志需要可见，但日志不包含密钥或完整客户截图。用户确认前不公开发布。

# 可访问网址的部署

项目源码可以在本地运行，但本地监听地址不是外网网址。生成可访问的网址需要用户提供服务器/部署平台访问权限及域名。当前没有进行外网部署，也没有取得公网网址。

## 单用户服务器部署

已提供 Dockerfile、compose.yaml 和 Caddyfile。适用：有 Docker Compose 的 Linux 服务器，域名已解析到服务器，80/443 端口可访问。SQLite 必须保存在持久卷中，不适用无持久磁盘的临时函数平台。

1. 将项目上传到服务器，保留原数据并先做备份。
2. 在服务器复制 `.env.example` 为 `.env`，设置至少12位的 `APP_PASSWORD`，并添加 `CRM_DOMAIN=你的实际域名`。不要把密码或密钥提交到Git，也不要发到聊天里。Compose 会按域名设置 `APP_ORIGIN`，应用端口只向容器内部暴露。
3. 如需真实分析，在同一文件填写自己的百炼接口地址、密钥与模型。未配置时仍可登录并体验固定示例，但不会分析真实截图。
4. 在项目目录运行 `docker compose up -d --build`，用 `docker compose logs app proxy` 检查启动和证书申请。Caddy 自动申请 HTTPS 证书，依赖正确DNS和网络访问。
5. 打开该域名的 HTTPS 地址，验证：未登录不能读取客户；登录后固定示例可审核保存；新建运输需求和报价；服务重启后数据保留。

应用数据位于 `crm-data` 卷。备份时先停止应用，并给备份容器挂载服务器上的备份目录：

```bash
docker compose stop app
docker compose run --rm --no-deps --volume "$(pwd)/server-backups:/app/backups" app node scripts/backup.mjs
docker compose start app
```

备份目录需允许容器的 node 用户（UID 1000）写入；保留数据库与截图。不要执行 `docker compose down -v`，它会删除持久卷。

## 部署平台

平台需要支持 Node.js 24+ 或此 Docker 镜像、持久磁盘、环境变量和 HTTPS。设置 `HOST=0.0.0.0`、平台分配的 `PORT`、持久磁盘内的 `DATA_DIR`、强密码 `APP_PASSWORD` 以及完整HTTPS访问地址 `APP_ORIGIN`。域名与APP_ORIGIN的Host应一致。

目前仅实现单用户密码登录；团队多账号和权限仍属于后续开发。使用真实聊天前，应验证百炼效果及数据备份恢复。
